TODO: Stack spoofing research (thread base frames)

Goal: after NtContinue into DllMain, the unwind walk should show a legit chain
      DllMain -> BaseThreadInitThunk -> RtlUserThreadStart (-> kernel stop)
      instead of dying at a stale/zero return address.

Why needed: NtContinue sets RIP directly and never pushes a return address, so
      DllMain's "caller" slot is garbage. RtlAddFunctionTable (done) only covers
      the payload's own frames; the base frames above it must be faked.

Key insight: RtlUserThreadStart / BaseThreadInitThunk are PRIVATE (not exported),
      so GetProcAddress won't find them. No scanning needed if we ask the OS.

Discovery trick (version-independent):
  1. CreateThread(NULL, 0, stub, NULL, CREATE_SUSPENDED, &tid)
     -> a suspended CreateThread thread has initial RIP = ntdll!RtlUserThreadStart
  2. GetThreadContext -> ctx.Rip == RtlUserThreadStart
  3. Stack already contains BaseThreadInitThunk (arg RtlUserThreadStart consumes)
     plus lpStartAddress + param. Dump ULONG_PTRs above ctx.Rsp and keep the one
     that falls inside kernel32's image range (base known from PEB).
  4. Alternative: read the real base frames off the loader's OWN thread stack
     (it was itself created via CreateThread) - higher addresses than RSP.

Spoof layout before NtContinue:
      [rsp+0x00] = ret into BaseThreadInitThunk   (as if it called DllMain)
      [rsp+0x08] = ret into RtlUserThreadStart    (as if it called BaseThreadInitThunk)

Caveats:
  - Don't hardcode stack offsets; identify values by module range.
  - Return-address slot normally points inside the function body; entry point is
    usually fine as long as it lands in [BeginAddress, EndAddress) of the .pdata.
  - Each frame must be self-consistent with its module's real .pdata, else the
    walk looks torn (worse than a clean gap). Verify with kb after wiring.
  - Suspended-thread trick doubles as a great debugging tool: dump context + stack
    once to observe exactly what a legit thread base looks like.

Syscall mechanism (biggest difference):
  - no 'syscall' instruction on x86; uses sysenter (KiFastSystemCall) or int 0x2E
    (KiIntSystemCall). Active stub pointer lives at fixed KUSER_SHARED_DATA
    address 0x7FFE0300.
  - find_gadget(): return *(DWORD*)0x7FFE0300 - NO ntdll scanning needed.
  - find_ssn(): SSN at offset +1 (stub is 'B8 xx xx xx xx'), not +4.
  - do_syscall: stdcall (args on stack, callee cleans up).
      * 'call dword [edx]' NOT 'jmp' - kernel expects 2 return addrs above args.
      * 'ret 48' to clean 12 params (12 x 4 bytes).
  - symbol decoration: x86 COFF stdcall = _do_syscall@48; match asm global +
    C prototype (__stdcall) name.

Loader logic to verify for 32-bit:

  - module overloading (NtCreateSection SEC_IMAGE + NtMapViewOfSection) is

  - NtContinue / RtlCaptureContext / RtlAddFunctionTable all have 32-bit forms
